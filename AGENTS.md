# Movie Engine — instructions for AI agents (Claude Code, Codex)

This file is the single source of instructions for every agent. `CLAUDE.md` only imports it.
Keep it current: whenever you learn something verified about the engine or a quirk, add it here or to the matching skill in `.claude/skills/`.
For people, start with `README.md`.

## What this project is

An AI-driven video production setup on top of the Kdenlive editor. The AI builds the editor project itself, the user reviews it in the running editor, then the AI redoes parts on request, or the user edits by hand, or both take turns. The user types prompts in Claude Code or Codex. Outputs are films and vertical shorts. Scriptwriting is out of scope.

## Rules

1. **Portable.** Everything needed to work lives inside this folder, so it can be copied to another computer. Never install into Program Files, never rely on the Windows user profile, keep media paths in projects relative.
2. **Do not disturb the user's desktop.** The user works on the same machine at the same time. Never steal focus, never send keystrokes or mouse input (no SetForegroundWindow, SendKeys, keybd_event). Drive the GUI only through UI Automation patterns (Invoke, ExpandCollapse, Window.Close) and capture only the editor's own window with `PrintWindow`. Never screenshot the whole desktop.
3. **Do GUI steps yourself.** Do not ask the user to click Save, Open and the like. Ask only for creative judgment and for permission (downloads, installs, deletions).
4. **The user sees the cut in the running editor** and may press Render themselves. AI edits must show up in the open Kdenlive (see the `kdenlive-live` skill).
5. **Materials from the internet:** before searching or downloading, ask the user what exactly is needed.
6. **Documents in Markdown** (`.md`).
7. **Talk to the user in their language.** Code, comments and these instruction files stay in English.
8. **The deliverable is the project.** Render what the work needs: scene and overlay clips for the timeline, and the frames or short ranges needed to check them. Do not render the final film or preview videos just to show unless asked.
9. **No quality compromises.** What Kdenlive cannot do is generated by external code (see below), never simplified or dropped.

## Engine: Kdenlive

- Portable official build `engine/Kdenlive/kdenlive-26.08.3_standalone/` (from download.kde.org, SHA-256 `a25427b1dff2c17e3b0386e991bb1a719382bb3176d1a90e441cdaeb6e0a967d`, unsigned 7-Zip SFX). `bin/` has `kdenlive.exe`, `melt.exe`, `kdenlive_render.exe`, `ffmpeg.exe`.
- Stock Kdenlive on Windows has **no external control API** (D-Bus is compiled only on Linux; verified in source v26.08.3). No fork is both popular and safe (survey 2026-11-21). Avoid lure repos such as `karen-5637/kdenlive-desktop`, `kdenlive-overview-2026`, `kdenlive-ai`.
- Upstream draft MR !902 (REST API for automation, 3 endpoints) is open; re-check after Kdenlive 26.12.
- Therefore the AI edits the `.kdenlive` file and makes the running Kdenlive re-read it ("File > Revert") through UI Automation. Skills: `kdenlive-live` (running editor), `kdenlive-project-file` (file format and melt).
- **Interface language.** The launchers start Kdenlive in English (`LANGUAGE=en_US`, set in `tools/kd-state.ps1` `Set-KdEnvironment` and the `.cmd` launchers). Set `MOVIE_ENGINE_UI_LANG` (e.g. `ru`) for another language. UI Automation finds items by name; the names it knows are in `tools/kd-ui.ps1` (`$KdNames`, `$KdInfoTitle`, `$KdRevertTitle`, `$KdProgressTitle`) for 31 languages: en, ru, uk, de, fr, es, pt_BR, zh_CN, ja, it, pl, ar, bs, ca, cs, da, el, et, fi, ga, hr, hu, lt, lv, nb, nl, ro, sk, sl, sv, tr. They are read from Kdenlive's own translations (`bin/data/locale/<lang>/LC_MESSAGES`: `kxmlgui6.mo` File, `kconfigwidgets6.mo` Save/Revert/Open Recent, `kdenlive.mo` the rest, `kwidgetsaddons6_qt.qm` Information), with `&` removed (CJK keeps the `(F)` accelerator). Another language needs its names added there and `tools/kd-langcheck.ps1` run with `MOVIE_ENGINE_UI_LANG` set to it (it finds File, Save, Revert and Open Recent; results in `docs/proof/language-<lang>.txt`). A language Kdenlive has no `kdenlive.mo` for (e.g. sw, am) shows English menus, which already work. Strings missing from a translation fall back to the Windows display language (a `de` check on a Russian Windows showed Russian "Мультимедиа").

### Not in git (see `.gitignore`)

`engine/Kdenlive/`, `engine/installer/`, `engine/profile-kdenlive/`, `engine/node/`, `node_modules/`, `out/`, `.shots/`, `materials/download/`. On a fresh clone (ask the user before downloading), `setup.cmd` / `engine\install.ps1` does steps 1-3 and skips what is already there (`-DryRun` shows the plan without downloading; exit 0 ready, 1 failed). By hand:
1. Unpack the Windows x64 `.zip` of Node.js 18+ from `https://nodejs.org/en/download` into `engine/node/`, so that `engine\node\node.exe` and `engine\node\npm.cmd` are there. A bare `node.exe` runs the scripts but has no npm for step 2.
2. `engine\node\npm.cmd install --prefix engine\voice` (versions pinned in `engine/voice/package.json`).
3. Download `kdenlive-26.08.3_standalone.exe` from `https://download.kde.org/stable/kdenlive/26.08/windows/` into `engine/installer/`, check its SHA-256 (above), unpack with `engine\installer\kdenlive-26.08.3_standalone.exe -o"engine\Kdenlive" -y` (7-Zip self-extractor, no admin).

### Before committing: no machine paths

The repository is public, so tracked files must not contain absolute paths of one machine (they expose the user's folders and user name, and break on another PC).
- **Kdenlive and `kdp.ps1` write absolute paths into every project they save**: the `root` attribute of `<mlt>`, the subtitle filter's `av.filename` (`.../<project>.kdenlive.ass`), and `kdenlive:docproperties.browserurl`. After a tracked project (e.g. under `projects/`) was opened, saved or rebuilt by a test, strip them before committing: drop `root="..."`, reduce `av.filename` to the bare `.ass` file name, delete the `browserurl` property. Edit byte-for-byte (keep CRLF; Git Bash `sed -i` drops the CRs), then check with `kdp.ps1 validate` and `kdp.ps1 frame`.
- A project without `root` is fine: `kdp.ps1` uses the project's own folder (`Resolve-KdpRoot`) and re-points the subtitle file on load (`Repair-KdpPaths`); verified 2026-11-23 with validate and melt frames (opening such a project in the Kdenlive GUI was not checked).
- Do not put scratchpad or TEMP paths, or the Windows user name (also its short form such as `ABCDEF~1`), into docs, skills or comments.
- Search before a commit: `git grep -n -I -i -E "C:[\\/](Users|other)|~1"`.

### Windows PowerShell gotchas (verified)

- Scripts containing non-ASCII text must be saved as **UTF-8 with BOM**, otherwise PowerShell 5.1 misreads them and fails to parse.
- Each tool call is a fresh shell: dot-source helpers in the same command that uses them.
- **Test Kdenlive instances run only through `tools/kd-hidden.ps1`** (own desktop, own profile, own TEMP `kd-hidden-<id>`, deleted when the run ends, so test folders do not pile up in the user's TEMP; copy anything you want to keep out of it inside the script). They cannot take the focus and cannot see the user's Kdenlive. Never start a test instance on the user's desktop.
- Never kill processes by name: other programs on the PC may run their own ffmpeg and node. Kill only a process id you started.
- **Launchers start Kdenlive only with `Start-KdDetached` (`tools/kd-state.ps1`).** `Process.Start` with `UseShellExecute=$false` passes the output pipe on (the caller hangs until Kdenlive is closed) and ignores `WindowStyle` (no minimized start). The splash also uses up the show flag, so the helper minimizes the main window without activation.
- **Never `FindFirst(Descendants)` from the Kdenlive main window of a loaded project.** On a 1000-clip project one such search freezes the editor for 30-70 s. Use the narrow finders in `tools/kd-ui.ps1`.
- A modal "Loading project" window is loading progress, not a blocking dialog (`Test-KdLoading`, `Wait-KdLoaded`).
- A native tool's exit code must be checked: a method exception in PowerShell does not stop a script without `$ErrorActionPreference = 'Stop'`.
- Variable names ignore case and collide with parameters (`$lock` with `-Lock`, `$t` with `$T`).
- `powershell -File` cannot take a value that starts with a dash after a space: write `"-FfArgs:-c:v libx264"`. Seconds use a dot, `2.5`.
- The Bash tool of Claude Code turns `\\` into `\` inside commands (so `\t` in a path becomes a TAB): write scripts with backslashes through the Write tool.
- **Never start Kdenlive as `kdenlive.exe <project>`**: with a file it lays out the panels after building the timeline, and each button change makes Qt walk every timeline item for UI Automation (~12 min on a 1000-clip project). Use the launchers: they start empty and open the project from Recent files (139 s).
- Kdenlive opening off-screen (running, but a taskbar click shows nothing): its saved window geometry in `engine/profile-kdenlive/AppData/Local/kdenliverc` (`kdockLayout`) is off-screen. To rescue a live window, move it with `SetWindowPos(h, 0, 0, 0, w, h, 0x0014)` (no activation).
- Copying project XML through `XmlDocument` needs `PreserveWhitespace = $true`: otherwise `Save` turns an empty `<property name="resource"></property>` into a line break, `kdenlivetitle` takes that whitespace for a file name, and titles vanish from melt frames and previews (bug found and fixed 2026-11-23; `kdp-clitest` "frame shows titles" guards it).
- `msedge-tts` puts the text into SSML unescaped: a bare `&` ends the stream with "Stream closed before the synthesis completed". `voice.mjs` escapes `& < >`.

## Status and open items

- What is proven, what failed and what is still open: `docs/kdenlive-proof.md`, raw results in `docs/proof/`. Read it before saying that something works. Do not claim coverage beyond what `docs/proof/` shows, and say which operations are equivalents.
- A project in the old format (1.04) raises a focus-stealing modal on its first save. Always write format 1.1 (`kdp.ps1 new`).
- Open:
  1. "Save As…" invoked via UI Automation on a minimized window opened no dialog (cause unknown).
  2. This Windows build has no sox, ladspa or movit MLT modules and lacks some frei0r/avfilter effects. The list is in `docs/proof/assets.txt`; `kdp.ps1` refuses them.
  3. Speech recognition needs Whisper or Vosk (a download: ask the user).
  4. Titles use fonts installed in Windows; on another PC a missing font must be installed, or the text rendered outside with a font from `engine/fonts/`.

### Editing tool

`engine\kdp.ps1` edits projects without the GUI; the command list is in its header, details in the skill `kdenlive-project-file`. Do not hand-edit project XML when a command exists.

- Linked audio+video halves follow move, trim, split, remove, slip and ripple-trim (`-Alone` for one half).
- Effect defaults are raw MLT values. **Never divide them by `factor`.**
- Job results go to `materials/aigenerated/<project>/<job>/`, never outside the project folder, never overwriting.
- Map of every Kdenlive menu action: `engine/tools/data/kdenlive-actions.csv` (`op` same operation, `equiv` another way or partly, `ui`, `na`).
- When you add or change an operation: update the map, add a check of the **result** to `kdp-clitest.ps1` (through the command line, not the function), run it with `-Report docs\proof\clitest.txt`, then run `kdp-coverage-check.ps1`. The coverage check fails while the proof is older than the code.

### What Kdenlive cannot do: render it outside, then put it in as a clip

Everything Kdenlive cannot do is generated by external code. Never simplify an effect, drop it, or accept a weaker look because Kdenlive lacks it. Kdenlive/MLT has no per-letter text animation, no expressions, little 3D, and heavy effects slow playback. Generate such parts outside and place the result on the timeline as an ordinary clip; the user still sees and edits the cut in Kdenlive.
- Make frames in code (PowerShell `System.Drawing`, ffmpeg filters, Lottie JSON, HTML/canvas), encode with the bundled `ffmpeg` to video with alpha (`.mov` with `-c:v png`, or WebM VP9 alpha), `bin-add` it and put it on a track above the pictures.
- Time it from data we have: word timings in `voice.json` let text appear exactly when the voice says it.
- Keep the generator script in `engine/tools/` (or the project's own folder) and its output in `materials/aigenerated/<project>/`, so the clip can be regenerated when text, font or timing changes (baked-in text cannot be edited in Kdenlive).
- Typical uses: per-letter kinetic text, animated highlights/arrows/circles over screenshots, counters, title cards, anything needing exact typography.
- Generators in `engine/tools/`:
  - `kinetic-text.ps1` — per-letter text cards, words timed from `voice.json`, highlight box; font loaded from `engine/fonts/` (Poppins Bold, OFL, not installed into Windows).
  - `annotate.ps1` — hand-drawn marker circles, boxes, underlines and arrows that draw on.
  - `card-entrance.ps1` — screenshot card rises and scales in over a still background, soft shadow; full-frame mp4.
  - `pdf-to-png.ps1` — slides from a PDF export.
  - `html-render.mjs` — any HTML/CSS/canvas scene to video (`engine\node.cmd engine\tools\html-render.mjs scene.html out.mp4`; `--frames 0,45` for check frames). Use it for interface animation, cursors, 3D, masks. It drives the headless Edge of Windows with a throw-away profile and no network. Keep `--sub` at 16: 4 motion-blur samples leave visible steps. Example: `examples/demo/scene/scene.html`. In a scene never set a child to `visibility: visible`, it shows through a hidden layer (use the empty value).
  - `film-render.mjs` + `film/` (`draw.js`, `film-kit.js`, `live.js`) — long interactive films on a canvas, about 45 frames/s on a mid-range GPU with real motion blur (about 20 times faster than `html-render.mjs`). One clip per VO line, one line of direction per shot, actions timed with `@word`. `--check` lists direction errors, `--shots all` gives a still of every shot: look at all of them before rendering. Example and commands: `examples/demo/film/film.html`. Compare every clip's frame count with the plan before placing.
  - Check renders of a big project: melt opens every bin file on load (over 2 minutes on a big project). Render from a copy without `main_bin` and unreferenced producers, never from a changed original.
  - Adding hundreds of clips: do not loop `Add-KdpMedia` + add (hours on a big project). Count ids once and write each playlist once (244 clips in 58 s), inside the usual lock / pull / hash / snapshot guard.
- Sounds shorter than a frame (`tick.wav`, 0.03 s) become empty timeline clips and `click.wav` is cut: pad them with silence first (`-af apad=whole_dur=0.0667`).
- Put overlays on their own track above the pictures and copy the picture clip's motion filters (push-in, whip) onto them so they move together; on a V1 picture the overlay has to fade itself where the V2 neighbours cross-fade over it.
- PowerShell trap: `[math]::Min(1, $v)` picks the **int** overload and rounds `$v`, so 0..1 animation progress jumps 0 -> 1. Type both arguments: `[math]::Min([double]1, $v)`.

### Edit cycle every agent must follow

1. `engine\kd-pull.ps1 -Project <file>` — the file now holds what the user sees (`kdp.ps1` does this itself).
2. Edit with `engine\kdp.ps1` (skill `kdenlive-project-file`).
3. If `kd-watch.ps1` is running for this project, the open Kdenlive reloads by itself; check `engine\kd-watch.log` for `AI change -> reload: exit 0`. Otherwise run `engine\kd-reload.ps1`. On exit 2 or a `CONFLICT` line the user edited in between: run step 1 again and re-apply your change on top.

Start the watcher once per session (hidden):
`powershell -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File engine\kd-watch.ps1 -Project projects\<name>\<name>.kdenlive` (from PowerShell use `Start-Process powershell -WindowStyle Hidden -ArgumentList ...`).

## Alternatives already evaluated (2026-11-21)

- **OpenShot 4.1.1** has an official agent CLI that drives the running GUI live with shared undo; it worked, Kdenlive was chosen for its editing depth.
- Blender VSE (blender-mcp, unauthenticated socket), DaVinci Resolve (scripting only in paid Studio), Shotcut (no control), web editors (immature) — not chosen.
